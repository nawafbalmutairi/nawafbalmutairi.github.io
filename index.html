01
Machine Learning · Dissertation

Benchmarking four ML models on
8.3 million water-quality samples.

KV6013 · 2026 · Final-year project

UK Environment Agency dataset, 2000–2025, five water-quality parameters. Mid-project, the upstream API was deprecated — so I rebuilt ingestion in Colab, batch-renamed 364 CSVs across 14 regions, and ran a chronological train/test split to benchmark Ridge, Random Forest, MLP, and XGBoost. The break became a system-design problem.

Python XGBoost scikit-learn PyTorch Pandas Power BI
Fig. 01 — WQ_ML_Benchmark_Dashboard.pbix · Summary view 2026 · Live artefact
i.The Brief

26 years of data,
one API outage.

Predict five water-quality parameters across 14 EA regions using 26 years of historical samples. Mid-build, the upstream Environment Agency API was deprecated (December 2025). Two choices: descope, or rebuild ingestion. I rebuilt it.

  • ~8.3M samples to ingest, partitioned by 14 EA areas × 26 years.
  • Five target parameters: Nitrate, BOD, Water Temp, Dissolved O₂, pH.
  • API deprecation cut the original Colab pipeline mid-flight.
  • Required a chronological train/test split — no peeking at the future.
Fig. 02 R² heatmap · 4 models × 5 targets · XGBoost on Water Temp leads at +0.785.
ii.The Method

Treat the break
as system design.

Rebuilt ingestion in Colab using the new beta endpoint, automated 364 CSV downloads, batch-renamed with PowerShell, and verified with a script that caught a swapped year in the Thames data. Then a chronological train/test split (train 2000–2017, test 2018–2025) — not a random split, because real forecasting can't see the future.

  • Chronological split avoids data leakage common in time-series ML.
  • Verification script flagged a year-number mismatch before training.
  • Same preprocessing pipeline across all four models for fair comparison.
  • Ridge / Random Forest / MLP / XGBoost — linear to non-linear coverage.
Fig. 03 RMSE & MAE benchmark · Detailed numeric comparison across all 20 model-target pairs.
iii.The Outcome · Model explorer
↓ Select a model to inspect its per-parameter R²
The Takeaway

"When an API breaks halfway through, you have two options: descope, or treat the break as system design.
The second answer is almost always better."

02
Business Intelligence · KV6011

NVIDIA AI-GPU
supply chain dashboard.

2025 · Power BI · Word count 3,632

An integrated BI solution for one of the world's most volatile supply chains. Using Soft Systems Methodology, CATWOE, and the Balanced Scorecard, I structured NVIDIA's AI-GPU forecasting problem from rich picture to KPI to live dashboard.

Power BI DAX Star Schema Soft Systems Methodology CATWOE Balanced Scorecard
Fig. 01 — Power BI dashboard · Production-ready artefact 2025
i.The Brief

A supply chain
running on fragments.

NVIDIA dominates AI-grade GPUs, but its supply chain is not the strength its P&L is. The H100, H200, and B-series depend on a single advanced-node foundry (TSMC), a bottlenecked CoWoS packaging step, and a demand signal that swings violently with every generative-AI release cycle.

Backorders accumulate. Forecasts misfire. The problem is structural, not local — a single dashboard cannot just report KPIs; it has to make the system visible.

  • Long supplier lead times — advanced-node + CoWoS packaging constraints.
  • Demand volatility — hyperscalers and AI startups order in waves.
  • Backorder accumulation directly threatens revenue predictability.
  • Data fragmented across orders, supply, inventory, and logistics systems.
Fig. 02 Rich picture · Soft Systems Methodology applied to the ecosystem.
ii.System Dynamics

Why production
won't fix this alone.

SSM tells you what is connected. A causal loop diagram tells you how those connections feed on themselves. High demand → backorders → pressure → production push → strain → lead times → more backorders.

Two reinforcing loops, two balancing loops. The conclusion: NVIDIA cannot fix this with manufacturing expansion — it needs an information-driven intervention.

  • Demand Surge — demand ↑ → backorders ↑ → pressure ↑ → strain ↑.
  • Forecast Volatility — volatile orders → forecast error → unstable inventory.
  • Capacity Constraint — limits force forecast revisions.
  • Lead Time Adjustment — delays force re-planning.
Fig. 03 Causal loop diagram — reinforcing (R) and balancing (B) feedback.
iii.Strategy

From insight to
scorecard.

CATWOE clarified ownership and worldview. The Balanced Scorecard translated insight into strategy: Learning & Growth capabilities feed Internal Processes, which improve Customer outcomes, which protect Financial performance.

Every KPI on the dashboard now has a place in the strategy. Nothing reports for its own sake.

Fig. 04 Strategy map — Balanced Scorecard linking capabilities to outcomes.

The Takeaway

CNN benchmark for

2024 · Computer Vision · 4 iterations

Benchmarked DenseNet121 against ResNet50 on Azure ML across four training iterations — tuning batch size, learning rate, and augmentation in isolated steps. PyTorch on GPU. Every iteration documented so the reasoning is reproducible, not just the final number.

i.The Brief

Two architectures,
one budget.

Build a binary classifier on facial images with a strict Azure ML GPU budget, two candidate architectures (DenseNet121 and ResNet50), and the requirement to justify every hyperparameter choice — not just report the final number.

Training samples / pipeline
Awaiting upload
Fig. 02 Pipeline: dataset → augment → train → evaluate.
ii.The Method

Change one thing,
measure the delta.

Identical preprocessing across both architectures, then a controlled iteration loop: hold all variables fixed except one, measure the delta, document the change. By iteration four, the dataset, augmentation, LR schedule, and batch size had each been independently stressed and tuned.

  • Same preprocessing for both models → architectural comparison is fair.
  • One change per iteration → effect of each hyperparameter is isolated.
  • All iterations versioned in Azure ML, so any run is reproducible.
